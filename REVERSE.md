# OpenSchool — разбор

Источник: `https://github.com/oxi-does-dev/openschool` (ветка `main`, коммит
`26c48ef`, запушен 2026-11-12 19:48). APK в `Download/sch*.apk` собраны из
этого же дерева.

## Что это

- пакет `ru.sch.diary`, label «Дневник», minSdk 26, targetSdk 34;
- в `Download` лежат сборки 1.4 (versionCode 5), в репозитории — 1.5 (6);
- ассеты совпадают побайтово (`assets/cdz-paper.js`, md5
  `fb5f7d01947d5337909aee9cf98d8d6e`) — значит APK действительно из этого
  репозитория;
- внутри только `classes.dex` (Java, без нативных библиотек), шрифты и один JS.

## Авторизация

Приложение не логинится по логину/паролю — оно забирает cookies школьного
сайта:

- вход через WebView на `https://school.mos.ru/` (страница логина mos.ru);
- либо импорт `cookies.json` с ПК: `Android/data/ru.sch.diary/files/`;
- cookies хранятся в `CookieManager` приложения, на ПК — в
  `~/.cache/sch/cookies.json`.

Ключевые cookies:

| cookie | смысл |
|---|---|
| `aupd_token` | bearer-токен МЭШ (главное) |
| `active_student` | id ученика (число) |
| `student_person_id` | `contingent_guid` для EJ-запросов |
| `aupd_current_role` | id роли для `X-Mes-RoleId` |

Заголовки каждого запроса:

```
Authorization: Bearer <aupd_token>
Cookie: <все cookies>
User-Agent: Mozilla/5.0 (Linux; Android 14) ... Chrome/156 ...
Accept: application/json, text/plain, */*
Referer: https://school.mos.ru/diary
X-Mes-RoleId: 1            (для EJ — id роли)
X-mes-subsystem: familyweb
Profile-Id: <student_id>   (только EJ)
Profile-Type: student      (только EJ)
```

401/403 → сессия протухла, нужен повторный вход. Запросы повторяются один
раз при 5xx и при обрыве сети. `java.net.preferIPv4Stack=true` — иначе
Android+VPN зависает на AAAA-записи `school.mos.ru`.

## API

Базы:

- `https://school.mos.ru/api/family/web/v1` — дневник;
- `https://school.mos.ru/api/ej/attachments/v1` — файлы/работы;
- `https://school.mos.ru/api/ej/rating/v1` — рейтинг;
- `https://school.mos.ru/api/ej/partners/v1` — запуск ЦДЗ.

| метод | путь | параметры |
|---|---|---|
| GET | `/profile` | — (id ученика, дети, `contingent_guid`) |
| GET | `/schedule` | `student_id`, `date` |
| GET | `/schedule/short` | `student_id`, `dates=a,b,c` (темы) |
| GET | `/homeworks` | `student_id`, `from`, `to` |
| GET | `/marks` | `student_id`, `from`, `to` |
| GET | `/marks/{id}` | `person_id` |
| GET | `/lesson_schedule_items/{id}` | `student_id`, `type=LESSON`, `person_id` |
| GET | `rating /rank/subjects` | `personId`, `date` |
| GET | `rating /rank/class` | `personId`, `date` |
| GET | `partners /homeworks/launch` | `homework_entry_id`, `material_id` (302, ссылка в теле) |
| POST | `ej /student_work` | `lesson_schedule_item_id`, `student_profile_id`, `work_type:"INDEPENDENT_WORK"`, `variant` |
| PUT | `ej /student_work/{workId}/variant` | `{variant:N}` (400 — дедлайн) |
| POST | `ej /files/by_student_work/{workId}/storage_access` | `{}` → `{file_uuid,file_link,token}` (400 — дедлайн) |
| POST | `ej /files/by_student_work/{workId}` | `{files:[...]}` (attach/delete) |

Ответ на создание — `StudentWork`: `{student_work_id, variant, files[]}`
(409 — работа уже есть; тогда id берём из повторного `GET lesson`).
Элемент `files[]` (`StudentWorkFile`) — `id` (uuid), `ordinal`, `type`
(расширение), `size` (строка, байты), `file_url`, `file_name`, `uploaded_by`
(`teacher`/`student`).

Протокол прикрепления (сверено с `ru.mes.dnevnik` 3.93.3, Hermes-бандл):

1. `storage_access` → `file_uuid` + `file_link` + `token`;
2. `multipart/form-data` POST на `file_link`, поле `content`, заголовки
   `Authorization: Bearer <token>` и `Content-Type: multipart/form-data`.
   Хранилище — отдельный HTTP-клиент, но МЭШ навешивает на него те же
   `commonHeaders`: `client-type: diary-mobile`, `X-Mes-Subsystem`,
   `Accept-Language: ru`, `Profile-Id`, `X-Mes-RoleId`;
3. `POST /files/by_student_work/{id}` с `{files:[…]}` — **только новые файлы**:
   - только что загруженный: `{file_uuid, file_name, size, order_number, extension}`;
   - уже прикреплённый: `{file_uuid, order_number}`;
   - удаление: `{file_uuid, deleted:true}`.

Все четыре EJ-запроса (create/variant/storage/attach) идут с `X-Mes-Subsystem`,
`Authorization`, `Profile-Id`; `Profile-Type` у МЭШ равен `parent` для
родительского профиля и `student` для детского.
В SDK имена операций содержат `…Family…` (`postApiEjAttachmentsFamilyV1StudentWork`),
но путь при этом обычный `/v1/student_work` — `/family/` в URL добавлять нельзя.


Скачивание файлов — тот же набор заголовков, `Accept: */*`, таймаут 60 с.

## Сборка в Termux (проверено)

В репозитории скрипт рассчитан на build-tools 35. Android SDK здесь есть,
но `aapt2` из SDK не запускается (конфликт protobuf), поэтому:

- `aapt2` — из Termux (`/usr/bin/aapt2`, 2.20);
- `d8` из build-tools 34 падает на классах от javac 21 → взят `r8-9.5.32.jar`
  с `dl.google.com/dl/android/maven2/com/android/tools/r8/9.5.32/`;
- `javac --release 11`, `zipalign`, `apksigner`, `keytool` — штатные.

Готовый скрипт: `android/build-termux.sh` → `android/build-local/sch-local.apk`
(795 КБ). Ключ подписи лежит в `android/.keys/` и переживает пересборку,
поэтому новые сборки встают поверх друг друга. Поверх *чужой* установленной
версии (`CN=sch diary` или оригинальной `CN=OpenSchool`) APK не встанет —
нужна переустановка с удалением.

Терминальная версия собирается как есть:

```bash
pkg install nlohmann-json libcurl sqlite openssl
cd cpp && make -j8        # -> build/sch
```

Использование: `sch today`, `sch marks 30`, `sch serve` (JSON API на
`127.0.0.1:8787`: `/day`, `/lessons`, `/hw`, `/homeworks`, `/marks`,
`/schedule`, `/schedule/short`, `/profile`, `/health`).

Локальная сессия: `~/.cache/sch/cookies.json`; `sch login` умеет вытащить
cookies из профиля Chromium (на Android Chromium недоступен — только
импорт файла).

## Что осталось

- cookies МЭШ на этом устройстве отсутствуют (`~/.cache/sch` пуст), поэтому
  `sch doctor` не проходит дальше поиска сессии;
- ключ подписи исходных APK (`CN=OpenSchool`, alias `sch`) в репозиторий не
  входит — для обновления «поверх» нужен он.

## Локальные доработки (ветка `local`)

- **родительский кабинет**: роль берётся из `aupd_current_role`
  (`ученик:2`, `родитель:3`, значение может быть url-encoded); для родителя
  `student_id` — это id ребёнка из `/profile.children`, а не `profile.id`;
  `X-Mes-RoleId` для family-запросов тоже равен роли из cookie; в шапке
  показывается ребёнок, взрослый подписан «родитель: …»; переключатель детей
  виден и при одном ребёнке;
- **прикрепление фото работы (ЦДЗ)**: окно урока → «Прикрепить фото работы»,
  до 10 файлов, фото жмутся в JPEG ≤2400 px; отправка создаёт работу
  (409 → переиспользует существующую), заливает файлы и прикрепляет их.
  Ошибки показывают HTTP-код и тело ответа МЭШ.
- **тёмная тема ЦДЗ**: кнопка в шапке окна задания (луна/солнце), состояние в
  `SharedPreferences` (`cdz_theme`: auto/light/dark, auto = тема приложения).
  `assets/cdz-paper.js` (v4) не трогает DOM и не воюет с React: он читает
  правила самого ЦДЗ через `document.styleSheets` и генерирует свои копии тех
  же селекторов со `!important` и префиксом `html.sch-dark` /
  `html:not(.sch-dark)`. Переключение темы — один класс на `<html>`, поэтому
  ничего не мигает и не перерисовывается заново. Inline-стили (их React может
  переписать) живут в `data-sch-d` / `data-sch-l` + сгенерированные правила,
  а не в `style`. Палитра берётся из `applyPalette()` один в один, без
  «похожих» оттенков: BG `#171613`, SURFACE `#201E1A`, SURFACE2 `#2A2721`,
  текст `#EAE3D5`, приглушённый `#A79D8B`, акцент `#8FB0D4`, ON_ACCENT
  `#171613`, STROKE `#3E392F`, DIVIDER `#35312A`, RULE `#4A4438`,
  CURRENT `#2C2A20`, RED `#D9827A`, GREEN `#85B394`, AMBER `#D6A960`,
  фиолетовый `#B79BC4`. Цветные плашки — `soft()` приложения (цвет + 0x22),
  кнопки — `ACCENT_SOFT` (0x2A8FB0D4) с текстом `ACCENT`, плотная акцентная
  заливка — `ACCENT` с текстом `ON_ACCENT`.
  Окно задания — во весь экран, вместо внутреннего загрузчика ЦДЗ показывается
  своя тёмная заставка со спиннером, которая плавно уступает место странице.
  Градиенты (`linear-gradient`, в том числе inline и на `var(--MH-*)`)
  перекрашиваются по стопам в полупрозрачные тона палитры — иначе фирменные
  фиолетовые баннеры и пилюли выпадали из темы. Тёмный логотип МЭШ в шапке
  скрывается (на тёмном фоне его не видно), остальные картинки не трогаются.
  Новые/дописанные таблицы стилей подхватываются (`scanSheets`, CSS-in-JS).

### Адаптивный нативный UI (2.3)

  `tight()` = ширина экрана < 340dp или `fontScale >= 1.3`. В этом режиме:

  - колонки времени (`08:30` / `до 09:15`) считаются по реальной ширине
    текста, а не фиксируются в 42/64dp;
  - оценки урока уходят под тему (`chipFlow`) вместо того, чтобы выжимать
    название предмета; ряд из пяти оценок переносится на вторую строку;
  - высота чипа оценки следует масштабу шрифта (`minHeight`, а не `dp(32)`);
  - пары кнопок (`buttonPair`) складываются в столбик, только если текст
    реально не помещается по ширине;
  - полосы чипов (ДЗ, оценки) прокручиваются по горизонтали (`chipStrip`);
  - диалог «Сеть и VPN» прокручивается и не теряет кнопки по высоте;
  - заголовки (шапка, месяца, недели, нижняя навигация) не переносятся
    бесконечно, а обрезаются с многоточием.

### 2.4: поведение и информация

  - **Назад** возвращает на «Дневник», а с другого дня — на сегодня;
    выходит из приложения только с сегодняшнего дня.
  - При возврате в приложение после 3 минут простоя открытая вкладка
    обновляется; если приложение простояло ночь, «сегодня» переезжает
    на новый день (и сохранённая дата тоже).
  - Если сеть отвалилась, но есть кэш, показывается плашка
    «Нет связи — данные от HH:MM» с кнопкой «Обновить»
    (день, неделя, ДЗ, оценки, итоговые, рейтинг).
  - `cachePut` пишет `key#at` — время фактического ответа сервера;
    «Очистить кэш» убирает и его, и `week3:`, `final2:`, `profile`.
  - В карточке ДЗ: «Копировать» и «Поделиться» (предмет, дата, урок,
    текст, материалы простым текстом).
  - В окне ЦДЗ — кнопка перезагрузки страницы.
  - «Ещё → Размер текста»: множитель 1.15 / 1.35 к системному шрифту
    через `attachBaseContext` + `Configuration.fontScale`; Activity
    пересоздаётся, `tight()` автоматически включает адаптивную вёрстку.
  - Для родителя в шапке дня показывается имя ребёнка, а не только класс.
  - В карточке дня ДЗ стало интерактивным: нажатие открывает подробности
    (файлы, материалы), а цифровое задание запускается кнопкой «Пройти ЦДЗ»
    прямо из дня — раньше это было только на вкладке ДЗ.
  - Сборка (`build-termux.sh`) теперь падает при ошибке `javac`: раньше
    вывод шёл через `grep -v`, и ошибки компиляции могли не остановить
    сборку.

### 2.5: тёмная тема ЦДЗ и дизайн-система

Экран ЦДЗ собран не только на токенах МЭШ (`--MH-*`/`--NC-*`), но и на
дизайн-системе Lemma (`--LM-*`, файл `7.383273e8.chunk.css` у `uchebnik`).
Раньше перекрашивались только токены МЭШ, поэтому шапка и кнопки были
тёмными, а карточки ответов, рамки, экран результата — светлыми.

  - `--LM-*` перекрываются точной палитрой приложения: `layer-background`
    (#171613), `layer-1` (#201E1A), `layer-2` (#2A2721), `content-primary`
    (#EAE3D5), `content-secondary` (#A79D8B), `border-*` (#3E392F),
    `shadow-*` (чёрные), `theme-<цвет>-*` — по ролям палитры.
  - У дизайн-системы есть собственный тёмный набор токенов, он включается
    классом на `<html>`. Класс включён с версии 7.383273e8 — версии нет,
    поэтому тёмный набор ищется в таблицах стилей по
    `--LM-layer-background` с тёмным значением и его класс добавляется/снимается
    вместе с темой (до 20 попыток, если CSS подгрузился позже).
  - `box-shadow`/`--*-shadow-*` перекрашиваются: светлая тень на тёмном фоне
    выглядела ореолом вокруг карточек; inset-светлые кольца → STROKE.
  - Рамки, заданные ссылкой на токен (`border:3px solid var(--MH-Color-School)`),
    сводятся к STROKE: у школы бывает насыщенный фиолетовый, и карточка
    результата получала толстую сиреневую рамку.
  - `--MH-Color-School` → ACCENT: плашка роли («УЧЕНИК») больше не сиреневая.
  - Плашка роли дополнительно помечается `data-sch-role`: ACCENT_SOFT +
    ACCENT, независимо от того, какие токены использовал сайт.
  - SVG, раскрашенные атрибутами `fill`/`stroke` (иконки, «уголки» рамок),
    перекрашиваются в TEXT — но только монохромные: цветные иллюстрации
    заданий не трогаются.
  - Логотип МЭШ ищется не только внутри `<header>`, но и по словесному знаку
    «мэш» в верхней части экрана (шапка бывает `<div>` с хешем).
  - Долгое нажатие на луну в окне ЦДЗ → «Отчёт о теме»: JSON со списком
    элементов, у которых остались светлые фон/текст/рамка/тень/картинка.
    Его можно скопировать или отправить.
  - `report()` доступен как `window.__schPaper.report()`. CSS-переменные (`--bg: #fff` + `var(--bg)`)
  тоже перекрашиваются, иначе половина сайта осталась бы белой. API:
  `window.__schPaper.set(true)`,
  `.isDark()`, `.rescan()`.

### 2.6: темы оформления

Кроме светлой и «тёмной бумаги» появились четыре темы: Full black, Nord,
Catppuccin (Mocha) и Gruvbox (dark). Настройка хранится в `theme`:
`auto`, `light`, `dark`, `black`, `nord`, `catppuccin`, `gruvbox`.

  - `applyPalette(theme)` в `MainActivity` задаёт один и тот же набор ролей
    (BG, SURFACE, TEXT, ACCENT, STROKE, RULE, GREEN/AMBER/RED/TEAL/VIOLET…)
    для всех тёмных тем; экраны приложения уже собраны на этих полях, поэтому
    перекрашиваются целиком.
  - Окно ЦДЗ получает палитру как `window.__schPalette` перед инъекцией
    `cdz-paper.js`. Ключи совпадают с ролями движка: `bg`, `surface`,
    `surface2`, `ink`, `muted`, `accent`, `onAccent`, `accentSoft`, `line`,
    `divider`, `rule`, `current`, `green`, `amber`, `red`, `teal`, `violet`,
    `errBg`, `errStroke`, `mark`.
  - Чтобы не дублировать CSS под каждую тему, базовый лист собирается из
    литералов тёмной бумаги (`PAPER_ROLE`) и перекрашивается `recolorCss()`
    в цвета активной палитры. Недостающие ключи берутся из тёмной бумаги,
    производные (`accentBg`, `onAccent`, `accentSoft`) считаются из акцента.
  - `__schPaper.palette(src)` меняет тему на лету: сбрасывает листы
    `sch-paper-site`/`sch-paper-dyn`, их кэши и заново сканирует стили сайта.
    `palette({})` возвращает «тёмную бумагу». Повторная инъекция скрипта
    читает `__schPalette` и сохраняет выбранную тему.
  - Диалоги рисуются системной темой, поэтому к `AppThemeDark` добавляется
    наложение `OverlayBlack/Nord/Catppuccin/Gruvbox` (`Theme.applyStyle`) с
    `alertDialogTheme` и своей рамкой `dialog_bg_*.xml`.
  - Проверки движка (126 штук) — `/data/data/com.termux/files/usr/tmp/levtest/cdztest.js`:
    Nord на живом DOM, смена на Full black и обратно, возврат к бумаге,
    сохранение темы при повторной инъекции.

### 2.7: итоги, калькулятор оценки и чек-лист ДЗ

Появилась вкладка «Итоги» (`TAB_STATS`). Она не переиспользует данные
вкладки «Оценки»: свой период (30 / 90 дней / учебный год) и свой кэш
`statsm2:<from>:<to>`, `statshw2:<from>:<to>`. ДЗ для итогов берётся за
30 дней назад и 14 вперёд.

  - Средний балл считается по весу (`weight`), как в карточке оценок.
    «Выйдет» — школьное округление из `Stats.gradeOf`: 5 с 4,56,
    4 с 3,56, 3 с 2,56.
  - Качество — доля 4 и 5 среди оценок с баллом; успеваемость — доля
    оценок без двоек. Оценки без числового балла («н», «осв.») в проценты
    не входят, но показываются отдельно.
  - Распределение 5/4/3/2 — те же строки `distRow`, что в подробностях
    оценок. Динамика — сравнение среднего первой и второй половины
    периода (только если оценок не меньше четырёх).
  - По предметам: средний балл, полоса, количество оценок, качество и
    количество каждой оценки. Нажатие открывает карточку с подробностями
    и кнопкой «В калькулятор».
  - Калькулятор: предмет (или все), цель 3/4/5, число будущих оценок.
    Нужный средний балл: `(порог * (вес + n) - сумма) / n`, где
    порог = 4,56 / 3,56 / 2,56. Сколько пятёрок подряд нужно —
    `ceil((порог * вес - сумма) / (5 - порог))`. Будущие оценки считаются
    с весом 1. Формулы вынесены в `Stats.java` и проверены отдельным
    JVM-тестом (17 проверок).
  - ДЗ: прогресс «сделано / всего», просроченные, на сегодня и завтра,
    разбивка по предметам и список невыполненного с галочками.
  - Галочка ДЗ локальная: `hwdone:<date>|<subject>|<time>|<entry>` в
    SharedPreferences. Если ключа нет, используется `is_done` из МЭШ;
    локальная отметка перекрывает ответ школы. В МЭШ ничего не
    отправляется — это написано и на экране.
  - На вкладке ДЗ появились фильтры «Все / Не сделано / Сделано» и
    карточка прогресса; галочка есть в каждой карточке. Позиция прокрутки
    сохраняется при перерисовке.

### 2.8: компактные фильтры ДЗ

Три ряда чипов на вкладке ДЗ (актуальные/прошедшие, период, отметка)
заменены одной строкой из трёх выпадающих списков: «Актуальные ▾»,

### 2.9: APK 859 КБ → 376 КБ без изменения внешнего вида

Вес почти целиком был в шрифтах: 1,29 МБ исходников, 648 КБ в сжатом
APK (78%). Полные файлы лежат теперь в `android/fonts-src/`, а в
`assets/fonts/` собираются субсеты скриптом `tools/subset-fonts.py`
(fonttools):

  - PT Serif Regular/Bold — кириллица, латиница до Latin Extended-A,
    пунктуация, валюты, стрелки, математика. Выброшены греческий,
    Ext-B, лигатуры fb00–fb04, таблица `kern` (кернинг остался в GPOS,
    которым пользуется Android) и name ID 13/14 с текстом OFL — сама
    лицензия лежит рядом файлом. Контуры оставшихся глифов побайтово
    те же: 541 глиф, расхождений 0.
  - Golos Text — переменная ось `wght` (95 КБ дельт) не нужна: приложение
    просит только 500 и 700. Собраны два статических начертания
    `GolosText-Medium.ttf` и `GolosText-Bold.ttf`, `loadFonts()` обновлён.
    Точки отличаются от вариативного оригинала максимум на 0,0005 em
    (округление при инстанцировании), ширины — до 0,5/1000 em.
  - Caveat — только цифры и знаки: 27 глифов вместо 753. Буквенные
    отметки («осв.», «н») `tvHand()` теперь рисует запасным PT Serif
    через `handOnly()`, иначе были бы пустые квадратики.

Дальше:

  - `build-termux.sh` собирает dex через R8 (`r8.pro`), а не D8:
    сохраняются только три класса из манифеста, остальное ужимается и
    переименовывается. Reflection в коде нет.
  - `tools/recompress.py` пересобирает APK с zopfli (обычный deflate,
    но плотнее): −10 КБ. Без установленного zopfli откатывается на
    zlib-9, сборка не ломается.
  - Иконки launcher'а переведены из PNG в lossless WebP: −9 КБ,
    пиксели совпадают.

Итог: 859 554 → 376 315 байт (−56%). Проверено: `aapt2 dump badging`,
`apksigner verify`, `zipalign -c`, 14 тестов `Stats`, 126 проверок темы
ЦДЗ, совпадение контуров шрифтов и пикселей иконок. На устройстве
внешний вид не проверялся — эмулятора нет.

### 2.10: Full black — чёрные поверхности, белые контуры

Тема `black` переписана под OLED: `BG #000000`, `SURFACE #050505`,
`SURFACE2 #0D0D0D`, `CURRENT #0A0A0A`. Разницу между карточкой и фоном
теперь даёт только рамка `STROKE #FFFFFF` толщиной 1 dp; `DIVIDER`
и `RULE` остались тёмными, чтобы внутренние линии не спорили с
контуром карточек.

Акцент в этой теме белый (`ACCENT #FFFFFF`), но рисуется не заливкой,
а контуром: флаг `outlineAccent` включает `accentPlate()` и
`accentRipple()` — чёрная плашка с белой рамкой и белым текстом.
Так сделаны выбранные чипы, основная кнопка, кнопки в диалогах ЦДЗ.
Чтобы выбранный сегмент отличался от остальных (текст везде белый),
`chipBg()`/`chipInk()` в Full black убирают рамку у невыбранных чипов
и делают их текст приглушённым.

Цветными остаются только смысловые оценки (`GREEN`, `AMBER`, `RED`,
`MARK4`) и ошибки. Точки предметов в этой теме белые: `SUBJECT_COLORS`
сведены к одному цвету. Окно ЦДЗ получает ту же палитру через
`paletteJson()`; `line` там тоже белый, поэтому границы блоков видны,
а заливки чёрные. Диалоги: `OverlayBlack`, `AppDialogBlack` и
`dialog_bg_black` перекрашены в `#000000`/`#050505` с белой рамкой.

Проверено: сборка, `apksigner`, `aapt2`, тесты `Stats` и 130 проверок
темы ЦДЗ (включая новую палитру Full black). Глазами на устройстве не
смотрел — эмулятора нет.

### 2.11: поля ответа ЦДЗ читаются в тёмной теме

Сайт в «результатах прохождений» красит набранный ответ не через `color`,
а через `-webkit-text-fill-color: #000`. Это свойство перекрывает `color`
и наследуется, поэтому прежние правила `html.sch-dark input{color:...}`
на него не влияли: поле становилось тёмным, а текст оставался чёрным.

Что сделано в `cdz-paper.js` (версия движка 7):

  - `ruleDecls()` и `evalInline()` теперь перекрашивают
    `-webkit-text-fill-color` так же, как `color`, а `colorProps()`
    считает его поводом пересчитать inline-стиль;
  - базовое правило для `input`, `textarea`, `select`, `[contenteditable]`
    и `[role="textbox"]` задаёт `-webkit-text-fill-color: currentColor`,
    поэтому текст следует за вычисленным цветом: обычный — светлый,
    неверный ответ — красный, а не глухо белый;
  - placeholder и автозаполнение WebView перекрашены отдельно,
    `option` в выпадающем списке получил тёмный фон;
  - `guardFields()` — страховка: если поздний стиль или inline
    `!important` всё же оставил тёмный текст на тёмном фоне, при фокусе
    и на каждом тике темы цвет правится инлайном (он сильнее селекторов);
  - `report()` теперь помечает такие поля как `fill`, чтобы диагностика
    их видела.

Проверено в jsdom: 140 проверок темы, включая поля с `!important`
в правиле сайта, inline-стиле и `!important` прямо в `style`, textarea,
contenteditable, select/option и красный неверный ответ. Контраст
ответа ≥ 7:1. На устройстве не смотрел — эмулятора нет.

### 2.12: кэш показывается сразу, сеть догружает молча

Заглушки загрузки (`skeletonDay`, `skeletonMarks`) должны появляться только
когда данных нет вообще. На деле часть вкладок вела себя иначе:

  - `fetchWeek()` вообще не читал `week3:*` из кэша: при первом открытии
    недели всегда рисовались пустые карточки, даже если неделя уже была
    загружена раньше. Теперь кэш поднимается до запроса, а сеть обновляет
    его следом.
  - `fetchProfile()` после удачного чтения кэша делал `return`, поэтому
    профиль никогда не обновлялся сам — только по кнопке. Теперь
    сохранённый профиль показывается сразу, а запрос продолжается.
  - `fetchFinal()` после кэша тоже выходил. Итоговые собираются по всем
    предметам (десятки запросов), поэтому добавлен TTL: свежий кэш
    (моложе 10 минут) не трогаем, старый обновляем в фоне.
  - `fetchDay()` теперь сам поднимает `day3:*`, если данные в памяти
    сброшены, а кэш остался.

Итог: на всех вкладках порядок один — сначала данные из кэша, затем
тихое обновление; заглушка только при полном отсутствии кэша. Ошибки
по-прежнему показываются плашкой «показаны сохранённые данные».

Проверено сборкой, `apksigner`, `zipalign`, тестами `Stats` и 140
проверками темы ЦДЗ. Визуально на устройстве не проверялось — эмулятора
нет.

### 2.13: акцентный цвет отдельно от темы

Цвет кнопок раньше был жёстко привязан к теме: в Full black — белый,
в Nord — голубой и так далее. Теперь его можно переопределить, не меняя
фон, карточки и цвета оценок.

  - настройка `accent` (ARGB, `0` — «как в теме») читается в конце
    `applyPalette()`, поэтому переживает смену темы и перезапуск;
  - при своём акценте `ACCENT`, `ACCENT2` и `ACCENT_SOFT` считаются из
    одного цвета, а `ON_ACCENT` выбирается по яркости: светлая заливка
    получает чёрный текст, тёмная — белый (`inkOn`);
  - в Full black явный акцент отключает контурный режим (`outlineAccent`):
    иначе от цвета осталась бы только рамка, а кнопка была бы чёрной;
  - `paletteJson()` уже передаёт `accent`/`onAccent`/`accentSoft` в окно
    ЦДЗ, поэтому смена акцента сразу видна и там;
  - «Ещё → Акцентный цвет»: 10 готовых цветов, «как в теме» и свой цвет
    тремя ползунками RGB с живым превью и подсказкой о цвете текста;
  - подвал «Ещё» больше не врёт про 1.6 — версия берётся из
    `versionName()`.

Проверено сборкой, `apksigner`, `zipalign`, тестами `Stats` и 140
проверками темы ЦДЗ. Визуально на устройстве не проверялось — эмулятора

### 2.14: округление итоговой оценки

Порог пятёрки был 4,50, поэтому средний 4,50–4,55 уже показывал «выйдет 5».
Теперь границы — 4,56 / 3,56 / 2,56: пятёрка начинается только с 4,56,
четвёрка — с 3,56, тройка — с 2,56.

`Stats.gradeOf()` сначала округляет среднее до сотых — то же число, которое
видно в интерфейсе, — и только потом сравнивает с порогом. Так 4,555,
показанное как 4,56, даёт 5, а 4,554 (4,55) ещё остаётся четвёркой.
`thresholdFor()` использует те же пороги, поэтому калькулятор «что нужно
до 3/4/5» и количество пятёрок подряд пересчитаны под новое правило.
Подпись под итогами обновлена, тест `Stats` расширен до 17 проверок.

### 2.15: именованные периоды на «Итогах»

Вместо «30 дней / 90 дней / учебный год» — «Неделя / Месяц / Триместр /
Год». Это не просто подписи: границы стали календарными, как их понимает
школа.

  - `STATS_WEEK` — с понедельника текущей недели (`mondayOf`);
  - `STATS_MONTH` — с 1-го числа текущего месяца;
  - `STATS_TRIMESTER` — с начала текущего триместра: сентябрь—ноябрь,
    декабрь—февраль, март—май (летом показывается последний, март);
  - `STATS_YEAR` — с 1 сентября текущего учебного года (`academicStart`).

Конец у всех — сегодня. Старые сохранённые значения `statsDays` (30, 90, 0)
при чтении переводятся в новые коды, поэтому после обновления выбранный
период не сбрасывается. Кэш статистики по-прежнему ключуется датами
`from:to`, так что смена периода не смешивает данные.

### 2.16: именованные периоды на «Оценках» и в ДЗ

Периоды стали общими для трёх вкладок. Коды `PERIOD_WEEK=-1`,
`PERIOD_MONTH=-2`, `PERIOD_TRIMESTER=-3`, `PERIOD_YEAR=0` и помощники
`readPeriod()`, `periodLabel()`, `periodDays()`, `periodStart()` живут в
одном месте.

  - «Оценки»: чипы «Неделя / Месяц / Триместр / Год», начало периода
    календарное (`periodStart`), конец — сегодня.
  - «ДЗ»: выпадающий список «Неделя / Месяц / Триместр» (года нет, чтобы
    не раздувать список и кэш). Для будущих заданий берётся N дней вперёд,
    для прошедших — N дней назад включая сегодня.
  - «Итоги»: те же коды, что и раньше, но через общий `periodStart`.

Старые ключи `marksDays`, `hwDays`, `statsDays` читаются только для
миграции: 7 → неделя, 90 → триместр, 0 → год, остальное → месяц. Новые
значения пишутся в `marksPeriod`, `hwPeriod`, `statsPeriod`.

Домашнее задание в «Итогах» по-прежнему берётся за фиксированные 30 дней
назад и 2 недели вперёд — там это подписано прямо в карточке, а не выдаётся
за выбранный период.

### 2.17: надёжное прикрепление фото работы

Нативное окно отправки считается не по локальным `HH:MM`, а по
`begin_utc`/`end_utc` из `GET /lesson_schedule_items/{id}`: это секунды UTC,
поэтому часовой пояс телефона и переход на летнее время ни на что не влияют.
Окно — от начала урока до `end_utc + 5 минут`
(`ACTIVE_EDIT_AFTER_LESSON_END_TIME_MS`).

Загрузка в хранилище теперь повторяет мобильный клиент не только телом
multipart, но и заголовками: `client-type: diary-mobile`,
`X-Mes-Subsystem: familymp`, `Accept-Language: ru`, `Profile-Id`,
`X-Mes-RoleId`. Относительный `file_link` достраивается от
`https://school.mos.ru`, сетевой сбой повторяется один раз.

Если окно закрыто, карточка урока больше не прячет секцию целиком, а пишет
«Загрузить работу можно во время урока и в течение 5 минут после
завершения» — как в МЭШ. Ошибки разделены по шагам (создание работы,
доступ к хранилищу, загрузка фото, привязка файлов), а фото, которые не
удалось отправить, остаются в списке для повтора, вместо того чтобы
пропадать вместе с успешными.

### 2.18: одна типографика и одна сетка

Шрифты получили строгие роли, без смешения внутри одного текста:

  - **Golos** — весь интерфейс, в том числе жирные подписи. Раньше
    `tv(..., bold=true)` неожиданно включал PT Serif Bold, поэтому мелкие
    надписи и время уроков набирались серифом;
  - **PT Serif** — только крупные заголовки через `tvSerif()` (название
    экрана, тема, предмет, число дня);
  - **Caveat** — только цифры оценок. Буквенные отметки («осв.», «н»)
    теперь рисуются Golos Bold, а не третьим шрифтом рядом с рукописной
    цифрой;
  - моноширинный — только сырой JSON в служебных разделах. Время уроков
    набрано Golos Bold, колонка держит ширину через `textColWidth()`.

Сетка: `PAD_SCREEN=16`, `PAD_CARD_H=14`, `PAD_CARD_V=12`,
`RADIUS_CARD=3`. Все контентные вкладки используют эти константы; карточки
дня, недели, ДЗ, оценок, итогов и профиля больше не отличаются полями на
2–4 dp. Состояния (нет сети, ошибка, пусто) выровнены по 16 dp. Нижняя
навигация выросла: иконки 22 dp, подписи 11 sp, строка 2 dp, больше воздуха
сверху и снизу.

### 2.19: шрифты ближе к Anthropic

Роли шрифтов не изменились, поменялись сами гарнитуры:

  - **Onest** (OFL, 100–900, кириллица) — весь интерфейс. Более
    геометрический и плотный, чем Golos: прямые терминалы, крупный x-height,
    спокойные цифры. В APK лежат две статические инстанции, 500 и 700;
  - **Source Serif 4** (OFL, 200–900, opsz 8–60, кириллица) — заголовки
    через `tvSerif()`. В APK — 400 и 600 при opsz 20. Контраст выше, чем у
    PT Serif, поэтому крупные заголовки выглядят «книжнее»;
  - **Caveat** — без изменений, только цифры оценок.

Настоящие гарнитуры Anthropic (Styrene и Tiempos) коммерческие и в APK
попасть не могут, поэтому взяты ближайшие по рисунку свободные аналоги.
`tools/subset-fonts.py` переписан под новые источники: у Source Serif 4
дополнительно фиксируется ось `opsz`, иначе в субсет попадают дельты
оптического размера. Субсеты занимают 579 КБ несжатыми, но APK остался
380 КБ — serif сжимается лучше, чем PT Serif.
